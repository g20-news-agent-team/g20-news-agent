# 系统架构基线

系统采用前后端分离和模块化单体后端，前后端及调度入口统一在一个 GitHub 仓库维护。业务使用统一的 PostgreSQL 数据库和 pgvector。各开发成员在本地使用独立数据库，通过 Alembic 迁移和约定的测试数据同步结构。

## 数据流与职责

团队指定媒体及官方来源 → 采集、清洗及去重 → 公共资料库 → AI 分析与检索 → REST API → 前端展示与选题工作台。

- `collection` 负责获取、解析及清洗外部材料。采集策略根据新闻来源的授权和访问要求确定。
- `corpus` 统一管理原文、官方通稿、来源、文本分段、检索索引和相关数据读写。业务功能复用同一资料库。
- `shared` 供应数据库、模型调用、检索、异常、日志和配置等公共能力。各模块保有自己的专项逻辑与提示词。
- `jobs` 提供定时任务入口，调用采集和相应业务模块。采集及调度可作为独立进程运行，随同一个后端项目维护。

## 接口与访问控制

前端通过 REST API 使用 JSON 传输数据，接口以 `/api/v1/` 为统一前缀。接口实现后生成 OpenAPI 文档供联调。用户使用独立账号，通过 Cookie 与服务端 Session 认证，FastAPI 负责对角色和资源访问进行校验。

## 详细设计待确认

数据库模型、索引、业务接口和模块细节等待团队评审。公共分析能力是否拆成独立的 `analysis` 模块仍待决定。环境连通性、进程部署、文件持久化与上线路径依据学校资源和运行验证确定。 [技术选型](tech-stack.md)
